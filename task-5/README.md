# Task5 — Проектирование GraphQL API для client-info

## Описание задачи

В сервисе `client-info` ранее использовался REST API, который предоставлял раздельные эндпоинты для получения:

- основной информации о клиенте;
- списка документов клиента;
- информации о родственниках клиента.

Такой подход приводил к высокой нагрузке из-за множественных REST вызовов, особенно в сценариях, когда потребителю данных нужны сразу несколько сущностей.

## Цель задачи

- Спроектировать GraphQL схему, которая обеспечит:

  - минимизацию количества сетевых вызовов;
  - гибкую выборку данных для различных потребителей;
  - отсутствие овер-fetching и under-fetching;
  - оптимизацию нагрузки на сервис `client-info`.

---

## Спроектированная GraphQL схема

- Выделены три основные сущности:

  - `Client` — основная информация о клиенте.
  - `Document` — документы клиента.
  - `Relative` — родственники клиента.

- Построена вложенная структура:

  - все связанные сущности доступны через объект `Client`.

- Определён корневой запрос `client(id: ID!)`, позволяющий получать все необходимые данные клиента в одном вызове.

---

## Ключевые преимущества решения

- Универсальный запрос для получения любых комбинаций полей.
- Существенное снижение RPS на `client-info` при сложных сценариях использования.
- Повышение скорости отклика для фронтенда и backend-сервисов.
- Простота расширения схемы при добавлении новых сущностей или полей.
